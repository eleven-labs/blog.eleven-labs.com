# Design Tokens

Design tokens are the abstract concepts our system is built on: color, spacing, typography and the like.

They are used instead of hard-coded values to ensure the flexibility and unity of all our product experiences.

## Where they live

Since the move to **Tailwind CSS v4**, the tokens are declared directly in CSS — Tailwind is configured
from a stylesheet rather than from a JavaScript file:

```
src
└───design-system
│   └───styles
│   │   └───theme.css       ← the tokens
│   │   └───base.css        ← global rules completing Tailwind's preflight
│   │   └───utilities.css   ← the few utilities Tailwind does not provide
│   │   └───index.css       ← entry point
```

`theme.css` holds a single `@theme` block. Every entry of that block becomes both a CSS custom
property and a family of utility classes:

```css
@theme static {
  --color-primary: #0a4084;
  --spacing-m: 24px;
  --radius-s: 4px;
}
```

```html
<div class="bg-primary p-m rounded-s">…</div>
```

## Tokens that change with the viewport

The whole typographic scale is bigger past the `md` breakpoint. Rather than duplicating every class,
the sizes are declared as custom properties redefined inside a media query, then referenced from
`@theme inline`:

```css
:root { --font-size-heading-xl: 40px; }

@media (width >= 1001px) {
  :root { --font-size-heading-xl: 64px; }
}

@theme inline {
  --text-heading-xl: var(--font-size-heading-xl);
  --text-heading-xl--line-height: var(--leading-base);
}
```

A single `text-heading-xl` class then covers both breakpoints, exactly as the previous design tokens
pipeline did.
